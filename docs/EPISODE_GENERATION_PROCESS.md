# OpenLectern Episode Generation Process (Low / Medium / High Parity SOP)

This document defines the standardized, deterministic workflow for generating any new episode (for example `ch06/p1`, `ch06/p2`, `ch07`, etc.) so that **Low / Medium reasoning levels ("hydrogen low/medium") achieve the exact same release-grade quality as High reasoning ("hydrogen high")**.

## Why Automated Gates Equalize Low, Medium, and High Reasoning

Previously, generating an episode required **High** reasoning effort because a single overlooked rule—such as leaving a legacy file in the folder, forgetting `dependencies` in `01_source_facts.json`, putting a Part 2 topic in Part 1's Scene 11 Rule 8, omitting the next-chapter forward bridge in Scene 10, setting `show: ["question"]` in `s09`, or overflowing a still by 4 pixels—only surfaced *after* a 20-minute video render or failed silently.

With OpenLectern's **`part:preflight` gate**, you do not rely on model memory to catch mistakes:
- **When to use High**: Initial book bootstrap (`course_map.json`), complex new visual template authoring under `src/`, or deep multi-file codebase refactors.
- **When Low / Medium works identically to High**: Generating subsequent parts/chapters (`ch06`, `ch07`, ...) using the **5-Gate Playbook** below, because every schema, math formula, pedagogy link, audio timestamp cue, pixel overflow, and packaging rule is mechanically checked with exit code `0` vs `1` before and after rendering.

## Mandatory Authoring Rules (Zero-Guesswork Checklist)

Follow every item below verbatim when writing a part's `01`–`08` artifacts:

### 1. Required Files Only (`S1`–`S9`)
Every part folder (`workspace/books/<book>/chapters/<ch>/<pt>/`) must contain:
- `01_source_facts.json` (must include `dependencies: { earlier: [...], later: [] }`, `quotes: []`, `terms: [...]`, `realWorldProblem`, typed `formula` and `numbers` blocks for all calculations)
- `02_content_audit.json` (generated by `node bin/openlectern.mjs run S4 --book <book> --chapter <ch> --part <pt>`)
- `03_concept_register.json` (`K01`..`Kxx`, every term & acronym expanded cleanly)
- `04_lesson_plan.json` (`coreConcepts` with 8 stages, `misconception`, `predictionQuestions`, `causalChain`, `sceneOutline`)
- `05_teaching_script.json` **and** `05_teaching_script.md` (100% synced beat IDs & narration with `08_episode.json`)
- `06_visual_brief.json` (topologies & `keyElements`)
- `07_storyboard.json` (template selection & beat intents)
- `08_episode.json` (complete visual data, bilingual `en` + `hi` narration, `visual.show` / `focus`, `visualCues`)

**Never keep deprecated legacy files**: delete `02_lesson_plan.json`, `03_math_blueprint.json`, or `04_pedagogical_script.json` if present. `part:preflight` fails immediately if any legacy file exists.

### 2. Scene Layout & Template Diversity (`P-01`..`P-10`)
A standard 12-scene `chapter_part` episode (`s00`–`s11`):
- **No template > 30%** (max 3 of 12, target max 2), **>= 5 distinct templates**, **no two consecutive scenes use the same template**.
- **`s00` (`hook`)**: `chat_story`, 4 beats (`s00b1`–`s00b4`), concrete stakes (`m1` novice question, `m2` trap/stakes, `m3` invention/mechanism, `m4` part roadmap), with `whereWeAre` (`current: 0`).
- **Mid-part (`s01`–`s08`)**: Include at least one `causal_chain` (or 5-step causal sequence), at least one `split_comparison` misconception split (`trap` vs `positive`), at least one `worked_example` passing mathjs six-way agreement (`C-13` & `C-14`: every variable in `formula.expression` must also appear in `formula.variables` and `given`), and at least one prediction question before reveal.
- **`s09` (`interactive_quiz`)**:
  - 3 fixed beats: `question` -> `thinking` (`pauseAfterMs >= 3000`) -> `reveal`.
  - **`visual.show` MUST be `[]`** on all 3 quiz beats (controls visibility via `visual.phase` only; non-empty `show` fails `A-06`).
  - Use a different numerical example than `s04`/`s07` worked examples (ground both sets of numbers in `01_source_facts.json` `facts`).
  - Every technical term & acronym in `question`, `options`, and `explanation` must have been defined in scenes `< 9` (`P-07`).
- **`s10` (`wisdom` + Forward Bridge to `nextPart`)**:
  - Verify `course_map.json` to see what `nextPart` is!
  - Include explicit spoken narration (`s10b3` or closing beat) in **every configured language (`en` & `hi`)** naming key concepts of the upcoming part (`nextPart.chapterNumber` / `partTitle` / topics).
  - Highlight the next part visually:
    - In `technical_panel` or `chat_story` with `whereWeAre`: set the final item to `"Next: ..."` and **`current` strictly less than `items.length - 1`** (`current = items.length - 2` shows a `NEXT` badge automatically).
    - Or use `roadmap` with a `"next"` item.
- **`s11` (`summary_thread`)**:
  - **Exact 6 beats** (`s11b1`–`s11b6`) and **exact 8 rules** (`r1`–`r8`).
  - `s11b1`: `visual: { show: [], range: [0, 0], compact: false }`, `visualCues: []`.
  - `s11b2` (`r1`,`r2`), `s11b3` (`r3`,`r4`), `s11b4` (`r5`,`r6`), `s11b5` (`r7`,`r8`): each beat's narration **must match its 2 displayed rules 1-to-1**, and **every single rule (`r1`–`r8`) must summarize content actually taught in `scenes <= quizIdx` of this part** (never put Part 2/future chapter concepts inside `r1`–`r8`).
  - `s11b6`: `visual: { show: ["r1".."r8"], range: [1, 8], compact: true }`, explicitly names `8 rules` / `सभी 8 नियम` in both `en` & `hi`, plus bridges forward when `nextPart` exists.

### 3. Math, Numbers, Acronyms & Layout Hygiene (`C-03`..`C-16`, `R-04`)
- **No raw `_`, `^`, or `$` in plain text strings**: Never write `F_0`, `S_0`, `N*`, `$100 - R$`, or `e^(rT)` in titles, card text, options, table cells, or narration. Put formatted equations inside `formula.latex` (double-escaped in JSON like `"\\frac"`) or `{ type: "math", latex: "..." }` RichText segments, and plain prose identifiers like `F0` / `F zero` / `N star`.
- **Grounding (`C-03`/`C-04`)**: Every number shown on screen (including wrong quiz options if not `isHypothetical`) or spoken in narration must appear in `01_source_facts.json`.
- **JIT Terms (`P-03`)**: Register every technical term and acronym in `03_concept_register.json`. Do not mention a `"new"` term/acronym in `s00` before defining it, unless defined right there (`means`, `is a`, `का अर्थ है`) with >= 15% word overlap with `plainMeaning`. Spell out casual currency/jargon (`dollars`, `euros`, `currency`, `over-the-counter`) in narration unless registered cleanly.
- **Narration-Visual Sync (`C-16` & `A-06`)**: Every visible element must overlap >= 15% with beat narration keywords, and every `visualCues` `anchor.<lang>` word must appear **verbatim** in that beat's spoken text in that language (`en` & `hi`).
- **Footer Length (`R-04`)**: Keep every scene's `takeaways[i]` concise (`<= 78` characters max) so Footer text never overflows 3+ lines. Keep `diagram_flow` node `sublabel`s short (`<= 28` chars).
- **UTF-8 & PowerShell Safety**: Always write Devanagari Hindi (`hi`) via UTF-8 (`fs.writeFileSync(..., "utf8")` or file tools—never PowerShell `Get-Content`/`Set-Content` ANSI). In Windows PowerShell, chain commands with `;` and check `$LASTEXITCODE`, never `&&`.

## The 5-Gate Execution Workflow

Execute these 5 gates in order for every part (`p1`, `p2`, ...) of `<book>` and `<chapter>`:

### Gate 1: Author Artifacts (`01`..`08`) & Clean Legacy Files
Author `01_source_facts.json`, `03_concept_register.json`, `04_lesson_plan.json`, `05_teaching_script.json/.md`, `06_visual_brief.json`, `07_storyboard.json`, `08_episode.json` and delete any deprecated legacy files.

### Gate 2: Run `S4` Math Audit & Pre-Compile Preflight
```powershell
node bin/openlectern.mjs run S4 --book <book> --chapter <ch> --part <pt>;
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE };
node bin/openlectern.mjs part:preflight --book <book> --chapter <ch> --part <pt>
```
Do **not** move to TTS synthesis (`S10`) until `part:preflight` prints `PREFLIGHT PASSED` with exit code `0`.

### Gate 3: Bilingual TTS Compilation (`S10`) & Fast `--stills` Overflow Gate
```powershell
node bin/openlectern.mjs run S10 --book <book> --chapter <ch> --part <pt>;
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE };
node bin/openlectern.mjs part:preflight --book <book> --chapter <ch> --part <pt> --compiled --stills
```
- **Why `--stills` before `S11`?** Rendering MP4 videos takes ~8–15 minutes per language, whereas `--compiled --stills` checks all TTS word-boundary `visualCues` (`A-06`) and renders every beat's `mid` & `end` still in Chromium to verify **0 `R-04` overflows and 0 `R-06` collisions** in ~30–45 seconds.
- If `--stills` reports any `A-06` or `R-04` error, fix the anchor word or shorten the overflowing text/box and re-run `S10` + `part:preflight --compiled --stills` first.

### Gate 4: Render (`S11`), Release QA (`S12`), Package (`S13`), and Index (`S14`)
Run sequentially for each part (`p1`, then `p2`, then `S14`):
```powershell
node bin/openlectern.mjs run S11 --book <book> --chapter <ch> --part <pt>;
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE };
node bin/openlectern.mjs run S12 --book <book> --chapter <ch> --part <pt> --no-review;
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE };
node bin/openlectern.mjs run S13 --book <book> --chapter <ch> --part <pt>;
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```
After all parts of `<ch>` finish:
```powershell
node bin/openlectern.mjs run S14 --book <book> --chapter <ch> --part p2
```

### Gate 5: Post-Render Release Audit, Code Check & Git Commit
Verify every part is truly releasable, packaged in `out/<book>/<ch>/`, free of stale drafts/flat files, and linked in `index.html`:
```powershell
node bin/openlectern.mjs part:preflight --book <book> --chapter <ch> --part p1 --release;
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE };
node bin/openlectern.mjs part:preflight --book <book> --chapter <ch> --part p2 --release;
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```
If any file under `src/`, `prompts/`, `tests/` changed, run `npm run check` (`eslint`, `tsc --noEmit`, `vitest run`) before committing changes to git.

## Fast Remediation Reference

| Code | Cause | Exact Fix |
|---|---|---|
| `S-01` (legacy) | Old `02_lesson_plan.json` / `03_math_blueprint.json` / `04_pedagogical_script.json` exists | Delete legacy files; write full `S1`–`S9` artifacts |
| `P-03` / `P-07` | Undefined term/acronym, or quiz uses un-taught term | Define term at first mention (`means` + plainMeaning words), remove premature mention from `s00`, or register term |
| `P-04` (bridge) | `s10` missing next-part spoken preview or `whereWeAre.current === items.length - 1` | Add `s10b3` naming `nextPart` topics in `en` & `hi`; set `whereWeAre.current = items.length - 2` |
| `P-08` | `s11` rules shifted vs `s11b2`–`s11b5` narration, or rule cites future part topic | Align `r1`–`r8` 1-to-1 with `s11b2`–`s11b5`, keep strictly within taught scenes, mention `8 rules` in `s11b6` |
| `C-03` / `C-04` | Number on screen or in narration missing from `01_source_facts.json` | Add the fact/calculation (including alternative comparison values if on quiz) to `01_source_facts.json` |
| `C-11` | Raw `_`, `^`, or `$` in plain string (e.g. `$N^*$`, `F_0`) | Replace with clean plain text (`F0`, `N star`) or structured `RichText` `{ type: "math", latex: ... }` |
| `C-13` / `C-14` | `WorkedExample` / `Formula` mismatch or undeclared `solvesFor` variable | Add `solvesFor` to `variables[]`; verify `mathjs` steps equal `result.value` |
| `A-06` | `visualCues` anchor missing verbatim or `s09` quiz sets `visual.show` | Pick exact single word spoken in that language; keep `interactive_quiz` `visual.show: []` |
| `R-04` | Text box overflows `scrollHeight > clientHeight` on still | Shorten card/takeaway/sublabel text and verify via `part:preflight --stills` |
